# 击杀夸奖与选择反馈：为什么一直没播（2026-11-20）

## 一、台词池规模

- **多杀夸奖**：48 句 = 自己 2/3/4/5 杀 × 4 个角色 × 2 变体（32）+ 队友 4/5 杀 × 4 角色 × 2 变体（16）。
  另有两条自动加料：复仇（「X 那笔仇报了！」）、击杀名单（「（亚索、盲僧）」）。
- **选择反馈**：72 句 = 4 角色 × {听劝、不听、连续不听} × {装备、海克斯} × 3 变体。

## 二、日志里实际发生的事（11-18 至 11-19）

```
语音队列 437 条：advice 362 / praise 256（人味句）/ chat 14
多杀夸奖（双杀/三杀/四杀/五杀）：0 条，从未进入队列
选择反馈：0 条（local-moments 只有 ended / death / idle）
在播的是人味句：来啦 8×、怪我 7×、输了 4×、我盯着呢 4×、赢啦 3×
```

## 三、原因一：推荐语措辞不匹配（已修）

`recommendedName()` 只认 `下一件|优先做|优先买|先买|先做|合成`，而模型实际说：

```
"下次能买时直接补狂热"     ← "直接补"
"下次能买时先补夺萃之镰"   ← "先补"
"先补十字镐合暴风之剑"     ← "先补"
```

解析不到推荐 → `settleChoiceReactions` 直接沉默（设计上"没有明确推荐就不评价"）。

**修法**：正则加入 `下件目标|直接补|先补|能买时补|可购买时补|补一件/个/把`，
并用真实播报做回归测试（4 条全部能认出推荐，判为"听劝"）。

## 四、原因二：多杀夸奖仍然没播（已加诊断，待下一局定位）

代码回放同一局日志能产出 6 条（5 双杀 + 1 三杀），说明文案与结算逻辑没问题，
是运行时没记录成链。可能的断点：`whoKilled()` 依赖 `state.me.riotId/summonerName`
与事件 killer 比对，身份字段丢失时全部归为 `other`。

**修法（诊断）**：每次 `streak >= 2` 的多杀事件，记一行到 `logs/multikill.jsonl`：

```json
{"at":…,"streak":3,"killer":"Noble丶Ys","side":"self|ally|other",
 "meChampion":"虚空掠夺者","meRiotId":"…","meSummoner":"…","allyNames":["…"]}
```

下一局结束后看这个文件就能确定：
- `side` 全是 `other` → 身份没对上（取名字段丢失）；
- `side` 正确但没有夸奖 → 链结算/播报环节的问题。
