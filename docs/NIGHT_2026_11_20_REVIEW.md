## 已修（0.2.64）

### 1. 129 次 400：提示词超了服务端上限

11-19 我把客户端上限从 2000 提到 2400 来给提示词腾空间，但服务端 `tasks.py` 硬校验
`1 <= len(message) <= 2000`，超出直接 400。129 次失败全部是这一条。

修法：客户端回到 2000，`fitPromptBudget` 目标 1950（留 50 字余量，先丢可选提示再截断）。

### 2. 多杀夸奖 0 条：宽限期比语音的新鲜度还长

诊断文件 `logs/multikill.jsonl` 记到 5 次 `side=self` 的双杀（23:18/23:28/23:37/00:17/00:20），
但语音队列里没有任何一条多杀文案。

原因：`settlePraise` 的云端宽限期默认 **30 秒**，而语音只朗读 `now - at <= 30 秒` 的条目。
夸奖在击杀后 32 秒才生成、且 `at` 用的是击杀时刻 → 永远落进"过期"，被静默丢弃。

修法：宽限期 30s → 6s；`at` 改用**播出时刻**（继续记录 `praiseChain` 供云端替换文案）。

### 3. 选择反馈 0 条：读错字段

`recommendedName()` 读 `b.text`，而教练播报落进 `state.broadcasts` 用的是 `broadcast` 字段
（`router.apply({...coach.lastReply, broadcast: ...})`）。取不到推荐 → 按设计沉默。

修法：`String(b.text ?? b.broadcast ?? '')`；新增回归测试用 `broadcast` 形态验证。
