# 提示词上限放宽（2026-11-21）

## 旧值 / 新值

| 位置 | 旧 | 新 | 说明 |
|---|---|---|---|
| 服务端任务校验 `tasks.py` | message ≤ 2000 字 | **≤ 8000 字** | 超了直接 400，模型不会被调用 |
| 服务端请求体 | 64,000 字节 | **128,000 字节** | 8,000 个汉字约 24KB，加上下文仍有余量 |
| 模型入参上限 `model_transport.py` | 60,000 字节 | **96,000 字节** | 消息变长后，system+tools+history 可能逼近旧上限 |
| 客户端发送上限 `cloud-agent.mjs` | 2,000 字 | **8,000 字** | 与服务器一致，不再出现「客户端肯发、服务器拒收」 |
| 提示词预算 `fitPromptBudget` | 1,950 字 | **7,800 字** | 留 200 字余量，超长仍先丢可选提示再截断 |

## 为什么之前是 2000

11-19 为修 413 曾把客户端临时提到 2400，但服务端硬校验仍是 2000 —— 结果 11-20 晚上
129 次请求被服务端以 400 直接退回（当晚 239 次请求里 54%）。这次两边一起放宽并保持一致。

## 代价（需要知道）

- 提示词变长 → 首字延迟与 token 成本会上升。实际只在「本局事实很多」时才用满；
  常见请求仍在 1300–1900 字区间。
- 若后续发现长局明显变慢，可以把「本局事实」做摘要而不是直接放宽上限。

- 客户端：0.2.65 已发布并安装。
